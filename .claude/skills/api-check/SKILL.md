# api-check: API 키 보안과 호출 점검

구조는 `브라우저(HTML/JS) → 서버 → 외부 API`다. 브라우저 코드는 누구나 열어볼 수 있어서 키가 한 번 노출되면 남이 내 요금으로 호출할 수 있다. OpenAI나 Gemini 같은 LLM API는 사용량 과금이 있을 수 있으므로 유출이 곧 요금 피해로 이어진다. 그래서 코드를 쓰거나 배포하기 전에 아래 순서로 점검한다.

## 점검 순서

### 1단계: 브라우저 쪽 코드에 키나 외부 API 주소가 있는지 (가장 중요)

HTML 파일, `<script>` 안의 코드, 브라우저에서 실행되는 `.js` 파일이 대상이다.

```bash
# 프런트 파일 위치는 프로젝트에 맞게 바꾼다 (예: public/, static/)
grep -rnE "(api[_-]?key|secret|token|password)\s*[=:]\s*[\"'`][^\"'`]{8,}" \
  --include="*.html" --include="*.js" .

# 브라우저가 LLM API를 직접 부르고 있는지
grep -rnE "api\.openai\.com|generativelanguage\.googleapis\.com" \
  --include="*.html" --include="*.js" .
```

- 키가 프런트에 있거나, 프런트가 OpenAI/Gemini 같은 유료 API를 직접 호출하면 **즉시 수정 대상**이다. 서버 엔드포인트(`/api/...`)를 거치도록 바꾼다.
- Gemini 호스트 주소는 위 값이 제가 아는 예시이므로, 정확한 주소는 공식 문서에서 확인한다.
- 키 없이 쓰는 공개 API(날씨, 공휴일 등)는 브라우저 호출이 가능하지만, 호출 한도가 있으면 서버 캐시를 권한다.
- 찾은 값은 **절대 그대로 출력하지 않는다.** 앞 4글자와 `****`만 보여준다. 점검 결과 자체가 유출 경로가 되면 안 되기 때문이다.
- URL에 키가 붙은 형태(`?key=...`)도 같은 취급이다. 가능하면 헤더로 보내는 방식이 있는지 해당 API 공식 문서에서 확인한다.

### 2단계: 서버가 키를 읽는 방식

서버 코드에서 키는 **환경변수로만** 읽는다. 언어는 프로젝트마다 다르므로(`process.env`, `os.environ` 등) 프로젝트의 서버 언어에 맞춰 점검한다. 서버 스택을 모르면 먼저 사용자에게 확인한다.

- 코드, 설정 파일, 주석에 키 값이 직접 들어 있지 않은지 확인한다.
- `환경변수 || "실제키값"`처럼 **기본값에 진짜 키를 넣은 코드**는 1단계와 같은 문제다. 기본값은 비워 두거나 에러를 내게 한다.
- 키가 없을 때 조용히 실패하지 않도록, 서버 시작 시점에 필요한 키가 있는지 검사하고 친절한 에러를 낸다.
- 배포 환경에서는 호스팅 서비스의 환경변수(Secrets) 설정에 키가 등록돼 있는지 사용자가 확인하도록 안내한다. 이 설정은 제가 직접 볼 수 없으므로 "확인하지 못함"으로 표시한다.

### 3단계: Git에 올라가면 안 되는 파일

`.gitignore`에 아래 항목이 있는지 본다. 없으면 추가한다.

```
.env
.env.*
!.env.example
*.pem
node_modules/
__pycache__/
```

`.gitignore`는 **앞으로** 올라가는 것만 막는다. 이미 올라간 적이 있는지도 확인한다.

```bash
git ls-files | grep -E "\.env"
git log -p --all -S "API_KEY" --oneline | head -50
```

### 4단계: 서버 엔드포인트 방어

서버가 공개돼 있으면 누구나 엔드포인트를 호출할 수 있다. 서버가 키를 대신 써주는 통로가 되지 않는지 본다.

| 항목 | 기준 | 이유 |
|---|---|---|
| 호출 횟수 제한 | 사용자나 IP당 제한이 있다 | 반복 호출로 요금이 폭증하는 것을 막는다 |
| 입력 검증 | 길이와 형식을 검사한 뒤 프롬프트에 넣는다 | 긴 입력으로 토큰 비용이 늘거나 프롬프트가 조작되는 것을 막는다 |
| CORS | 허용 도메인을 지정했다 (`*` 아님) | 다른 사이트가 내 서버를 마음대로 호출하는 것을 막는다 |
| 에러 응답 | 외부 API 원본 에러, 키, 헤더를 브라우저에 보내지 않는다 | 에러 화면을 통해 키가 노출될 수 있다 |
| 접근 제어 | 로그인 없이 공개라면 위험을 사용자에게 알린다 | 인증이 없으면 누구나 LLM을 호출할 수 있다 |

### 5단계: 외부 API 호출 코드

| 항목 | 기준 | 이유 |
|---|---|---|
| 타임아웃 | 모든 호출에 건다 (권장 10초) | 응답이 없을 때 서버가 무한정 멈추는 것을 막는다 |
| 예외 처리 | 실패를 잡아서 해당 기능만 대체 응답을 준다 | API 하나가 실패해도 나머지 기능은 동작한다 |
| 상태 확인 | 401, 429 같은 상태 코드를 확인한다 | 오류를 정상 응답으로 착각하지 않는다 |
| 캐시 | 같은 결과는 저장해 재사용한다 | 무료 호출 한도와 요금을 아낀다 |
| 로그 | 키, 전체 URL, 요청 헤더를 로그에 찍지 않는다 | 로그를 통해 키가 새는 것을 막는다 |

### 6단계: LLM 비용 방어 (OpenAI, Gemini 등)

- 접속할 때마다 호출하지 않고, 하루 단위로 생성한 결과를 저장하거나 캐시한다.
- 응답 길이 상한(max tokens 등)을 설정한다. 파라미터 이름은 API마다 다르므로 공식 문서에서 확인한다.
- 사용자 입력 길이를 제한한다.
- 각 서비스의 대시보드에서 사용 한도나 예산 알림을 설정하도록 안내한다. 설정 위치와 기능은 서비스마다, 시기마다 다를 수 있으므로 공식 화면에서 확인하라고 말한다.
- OpenAI와 Gemini 중 어느 쪽을 쓸지 정했다면, 모델명은 코드 한 곳에서 상수로 관리한다.
- 무료 한도와 요금은 확인하지 못했다면 사실처럼 말하지 않고 "공식 문서에서 확인 필요"로 적는다.

### 7단계: 프런트엔드 출력 안전

- 사용자 입력과 LLM이 만든 문구를 `innerHTML`로 넣지 않고 `textContent`로 넣는다. 그렇지 않으면 악성 스크립트가 실행될 수 있다.
- `localStorage`에 키나 개인 정보를 저장하지 않는다.

### 8단계: 새 API를 붙이기 전 확인

- 키가 필요한가? 무료 플랜의 호출 한도는 얼마인가?
- 상업적 사용, 재배포, 출처 표기 조건이 있는가?
- 호출을 서버에서만 하는가? (키가 필요한 API는 반드시 서버)

확인하지 못한 내용은 사실처럼 말하지 않는다.

## 키가 이미 유출됐다면

GitHub에 올렸거나, 프런트 코드에 있었거나, 채팅·스크린샷에 보였다면 아래 순서로 안내한다. **키를 지우는 것보다 폐기가 먼저다.**

1. 해당 서비스(OpenAI, Google 등)의 대시보드에서 그 키를 **즉시 폐기(revoke)하고 새 키를 발급**한다. 파일을 지워도 이미 복사됐을 수 있기 때문이다.
2. 새 키를 서버 환경변수와 배포 환경의 Secrets에 교체한다.
3. 사용량 내역에서 모르는 호출이 있는지 확인한다.
4. Git 기록에서 제거하는 작업은 폐기 이후에 선택적으로 한다. 저장소 기록을 다시 쓰는 일이라 위험하므로, 실행 전에 사용자에게 설명하고 확인을 받는다.

## 결과 보고 형식

점검이 끝나면 아래 형식으로 짧게 보고한다. 키 값은 절대 쓰지 않는다.

```
## API 점검 결과

**위험 (바로 수정):**
- index.html:48 — 브라우저에서 LLM API를 직접 호출 → 서버 엔드포인트로 교체

**주의 (권장):**
- server 호출 코드 — 타임아웃 없음

**통과:**
- .gitignore에 .env 포함

**확인하지 못함:**
- 배포 환경의 환경변수 설정

**다음에 할 일:**
1. (가장 급한 것부터)
```

- 위험 항목은 고친 코드를 **먼저** 보여주고, 왜 그렇게 고쳤는지 이유를 덧붙인다.
- 어려운 용어(revoke, rate limit, CORS 등)는 처음 나올 때 한 줄로 풀어서 설명한다.

## 하지 말 것

- 사용자의 실제 키를 채팅, 로그, 파일, 커밋 메시지에 쓰거나 되풀이하지 않는다.
- 사용자가 키를 대화에 붙여넣었다면, 그 키는 노출된 것으로 보고 폐기를 권한다.
- 사용자의 승인 없이 Git 기록을 바꾸거나 파일을 삭제하지 않는다.
- 확인하지 않은 API 요금, 한도, 약관을 사실처럼 말하지 않는다.
